## Findings considered and rejected (do not re-audit)

- **Atomic ETag↔payload snapshot** (handler/show.go computes the ETag, then re-reads for the body): the race's worst case is one unnecessary 200 or one poll of staleness, self-healing; a snapshot would add transaction scope to the hottest read path. Documented in plan 003 instead.
- **`writeJSON` switching back to buffered `json.Marshal`**: streaming keeps memory flat on multi-MB payloads; the mid-stream-failure case (truncated 200) is logged as of plan 003 and effectively unreachable for self-owned envelope types.
- **Negative `limit` handling in `handler.pagination`**: the service layer clamps (`clampLimit`); double-clamping adds nothing.
- **Editor `seatIndex.ts` vs renderer `spatialIndex.ts` unification**: different concerns (row-centroid caching vs uniform-grid hit-testing); merging would over-generalize two small, tested modules.
- **Rate-limiter bucket-map OOM**: GC evicts 5-min-idle buckets every minute; attacker-driven growth requires XFF spoofing (backlog #3) and even then the math doesn't reach OOM at the configured RPS.
- **CORS wildcard+credentials hazard**: current implementation is spec-compliant (wildcard only without credentials); revisit only when auth lands.
- **`SeatStatuses` vs `SeatStatusesJSON` duplication in the store**: intentional layering (Go-typed path for logic, pg-serialized path for the hot read); not dead code.
- **Scene JSONB→TEXT migration risk**: verified — nothing queries inside the scene column; migration `0002` is idempotent and tracked by the runner's `schema_migrations`.
- **Editor `window.__EDITOR__` bridge**: correctly gated to non-production (`app/editor/context.tsx:28`); by design.
- **"The API has no auth"** as a finding: AUTH_ENABLED scaffolding is a deliberate, documented decision. The *actionable* slice is captured as direction (wire an API-key authenticator + enable for admin mutations before any public deployment) and backlog #6.
- **Editor double-save / double-click guards, rAF-after-unmount, resize-listener fragility** (web audit WEB-04/05/06/08/10): defensive-programming grade, partly unconfirmed (`isSaving` is already plumbed into the save UI); none reproduce as user-visible bugs.
- **PostCSS advisory**: rides along with plan 005's Next bump (transitive).
